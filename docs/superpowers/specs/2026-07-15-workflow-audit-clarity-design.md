# AI 工作流审计台易读性改版设计

日期：2026-07-15
状态：已确认

## 1. 背景与问题

现有 `/debug` 工作流审计台已经能够展示文档处理与问题回答的完整链路，但页面主要面向技术排障：步骤平铺较长、英文状态码直接暴露、多个关联文档重复展示同一套处理步骤，且“历史重建”没有说明数据来源和可信边界。

本次改版面向需要理解业务流程的管理员和开发人员。目标不是减少审计信息，而是让用户先看懂“系统做了什么、为什么做、结果意味着什么”，需要排障时再进入技术明细。

## 2. 设计原则

- 业务解释优先，技术细节后置。
- 每一步始终显示一句固定中文解释。
- 不改变现有审计采集、RAG、权限和持久化数据结构。
- 无法确认的历史信息明确留空，不使用伪造耗时或配置。
- 多文档问答一次只展开一个文档处理链，避免重复信息淹没问题处理链。

## 3. 页面结构

保留现有顶部运行工具栏和历史回放选择器。主体由原纵向平铺时间线改为四张业务阶段卡片：

1. **文档准备**：上传与登记、内容解析、知识对象生成、切块、Embedding、持久化。
2. **问题检查**：输入安全检测、范围判断、权限过滤。
3. **寻找依据**：查询信号、三路召回、融合重排、上下文扩展、证据闸门。
4. **生成与核验**：结论生成、引用装配、答案反思、最终输出。

四张阶段卡片默认全部展开。用户可以手动收起阶段；包含失败或拦截步骤的阶段始终优先展开。

每个步骤行固定展示：

- 步骤名称。
- 一句话说明“这一步在做什么”。
- 本次运行的业务结果摘要。
- 已完成、执行中、已拦截、失败或已跳过状态。

步骤行不直接展示 `objects_generated`、`persisted`、`fallback_applied` 等内部状态码。

## 4. 多文档展示

当一次问答关联多个文档时，“文档准备”阶段顶部显示文档切换器，优先选择主要命中文档；无法识别主要命中文档时选择关联列表中的第一份。一次只渲染所选文档的六个处理步骤。

切换文档只改变“文档准备”阶段，不改变本次问题处理的十二个步骤。切换器显示文档名称或可识别的文档 ID，并标注记录类型：真实记录或历史回溯。

## 5. 历史回溯定义与文案

原“历史重建”统一更名为：

> 历史回溯（非当时日志）

当所选文档使用回溯数据时，在文档切换器下方固定显示：

> 该文档在审计功能上线前已存在。以下步骤根据当前保存的文档、切块和表格数据补画，不代表当时真实执行记录；当时耗时、模型配置和告警无法确认。

历史回溯不代表系统重新处理了文档，也不反向补造当时的时间戳、模型或告警。步骤结果只展示当前持久化状态能够证明的事实。

## 6. 十八个步骤的固定解释

### 6.1 文档准备

- **上传与登记**：记录文件名称、类型、所属城市和访问权限。
- **内容解析**：读取正文、标题和表格，转换为系统可处理的内容。
- **知识对象生成**：识别条款、指标、定义、清单和材料要求。
- **切块**：把长文拆成可独立检索的小段，同时保留上下文。
- **Embedding**：把文字转换为语义特征，用于查找意思相近的内容。
- **持久化**：保存处理结果，使文档正式进入知识库。

### 6.2 问题检查

- **输入安全检测**：检查问题是否包含提示词注入或越权要求。
- **范围判断**：确认问题是否属于当前知识库能回答的范围。
- **权限过滤**：排除当前提问账号无权查看的资料。

### 6.3 寻找依据

- **查询信号**：识别问题中的关键词、条款号、数值和专业术语。
- **三路召回**：分别通过精确、关键词和语义方式寻找资料。
- **融合重排**：合并重复内容，把最相关的证据排到前面。
- **上下文扩展**：补充命中条款的标题、上下文和关联表格。
- **证据闸门**：判断现有资料是否足以支持明确结论。

### 6.4 生成与核验

- **结论生成**：仅依据通过检查的证据生成回答草稿。
- **引用装配**：为结论匹配来源文件、章节、页码和表格。
- **答案反思**：检查答案是否完整、是否与证据冲突。
- **最终输出**：根据检查结果正常回答、降级提示或拒绝回答。

## 7. 步骤详情

点击步骤后，右侧详情面板优先展示三个业务区块：

1. **这一步做什么**：固定中文解释。
2. **为什么需要这一步**：说明该步骤在完整链路中的作用和风险控制目的。
3. **本次结果怎么看**：把当前 metrics、decision 和 outputSummary 翻译成通俗结果。

技术信息放入默认折叠的“技术明细”区域，包括：

- 耗时。
- 内部状态码和原因码。
- 检索候选、得分和数量。
- 脱敏后的输入、输出和原始 JSON。

历史回溯步骤的耗时显示“历史数据无法确认”，不显示破折号或 `0 ms`。

## 8. 展示词典

新增独立的工作流展示词典，根据步骤 key 提供：

- 业务阶段。
- 固定解释。
- 步骤作用。
- 结果摘要格式化函数。
- 内部 outcome 到中文结果的映射。

展示词典只读取现有 `WorkflowStep` 和 `WorkflowTrace`，不参与审计记录、检索或答案生成。无法识别的新步骤使用安全兜底文案，并继续在技术明细中展示原始脱敏数据。

## 9. 响应式布局

- 桌面端保持左侧阶段卡片、右侧步骤详情。
- 窄屏下步骤详情移动到当前所选步骤下方。
- 文档切换器在窄屏下占满整行。
- 长文件名、解释和结果允许换行，不压缩状态图标。

## 10. 错误与特殊状态

- **已拦截**：显示触发的业务原因，例如“检测到越权请求，未进入检索”。
- **失败**：显示经过脱敏的简短失败说明，技术异常放入技术明细。
- **已跳过**：说明由哪个前序步骤终止，不把跳过误写为成功。
- **兜底输出**：明确说明是否替换草稿、要求核对原文或拒绝回答。
- **历史回溯**：每个相关步骤保留回溯来源标识，但不重复显示大段提示；完整提示固定显示在文档切换器下方。

## 11. 测试与验收

### 11.1 单元测试

- 十八个已知步骤都具有阶段、固定解释和作用说明。
- outcome 和状态能够映射为中文结果。
- 历史回溯耗时不会显示为真实耗时。
- 指标摘要只使用可确认字段并对缺失值安全降级。
- 多文档选择只返回当前文档的六个步骤。

### 11.2 页面验收

- 页面首屏不再出现英文技术状态码。
- 每一步始终可见一句中文解释。
- 四个业务阶段完整覆盖六个文档步骤和十二个问题步骤。
- 多个关联文档一次只显示一个文档处理链。
- 历史回溯说明始终可见，并明确“不是重新处理，也不是当时日志”。
- 点击步骤后能看到“做什么、为什么、结果怎么看”。
- 技术状态码、候选得分和脱敏 JSON 仍可从技术明细查看。
- 正常回答、提示注入、权限拒绝、证据不足和兜底输出均能用中文解释。

### 11.3 回归验证

```powershell
npm.cmd test
npx.cmd tsc --noEmit
npm.cmd run build
```

启动本地服务后，至少验收一条正常问答、一条提示注入阻断和一条包含历史回溯文档的记录。

## 12. 非目标

- 不修改审计数据模型或重新处理旧文档。
- 不新增外部日志平台或数据库。
- 不改变现有管理员/开发人员权限边界。
- 不删除开发调试所需的技术明细。
- 不实现自由拖拽流程画布。
