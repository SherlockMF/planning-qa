# 复杂规模单元格分档修复设计

日期：2026-07-30  
状态：已批准并实施首版

## 1. 背景

配置指标表中「一般规模」单元格常把多档配对写在同一格内，例如机构养老设施：

```text
50-100 床
2000-4000

100-500 床
4000-15000
```

当前链路有两处结构性损失：

1. **抽表丢行**：Python `extract_ordered_cell_text` 用 `"".join(lines)` 拼接视觉行；TypeScript `normCell` 再去掉 `\n`。结果变成 `床50-1002000-4000` 一类粘连脏值。
2. **回答再拍平**：即便拆成两行，结论/「自动提炼草稿」仍可能合成 `50-500床，2000-15000`，丢失「床位档 ↔ 建筑面积」配对。

现有低保真闸门能挡住部分脏数正式结论，但草稿仍可能胡说，且无法在解析成功时给出可解释的分档答案。

## 2. 目标与非目标

### 2.1 目标（两者都要）

1. **能解析则结构化答对**：保留分档配对，禁止拍平成单一宽区间。
2. **不能解析则拒脏数**：正式结论与自动草稿均不得引用粘连/乱序数值；引导核对原文页。

### 2.2 首版范围

- 仅覆盖**配置指标表**中「一般规模」相关单元格的**床位档 ↔ 建筑面积**分档模式。
- 以「机构养老设施」所在页为金标闭环样例。
- 旧文档不自动批量重跑；对目标 PDF **显式重新解析**后生效。

### 2.3 非目标

- 不一次修所有复杂表（千人指标同格多行、跨列表述、图纸类 PDF 等另立项）。
- 不让 LLM 参与单元格结构恢复。
- 不在审核页手改表格回写索引。
- 不改变既有权限、检索融合权重的总体架构。

## 3. 方案选择

采用「结构前移 + 回答安全闸」：

| 方案 | 结论 |
|------|------|
| A. 只修回答层 | 拒绝：永远答不出分档配对 |
| B. 只保留 `\n` + 正则 | 部分有效，但缺规范对象与金标闭环 |
| C. 抽表保行 → 分档展开 → 回答双闸门 | **采用** |

## 4. 数据流

```text
PDF 单元格视觉行
  → 抽表保留行分隔（\n），禁止无缝拼接
  → Canonical / TableModel 单元格保留分行文本
  → 分档展开器：匹配则拆成多条逻辑指标行；失败则标 lowFidelity
  → indicator_item / chunk（带分档字段）
  → 回答：分档渲染；低保真时正式结论与草稿同时降级
```

## 5. 组件设计

### 5.1 抽表：格内保行

**Python**（`scripts/extract_tables.py`）

- `extract_ordered_cell_text`：视觉行用 `\n` 连接，不再 `"".join` 无缝拼接。
- `clean_cell_text`：不得删除行分隔所需的换行；可继续修单位乱序，但不得把两行数值粘成一行。

**TypeScript**

- `normCell` / 等价归一化：保留 `\n`，只压缩同行内空白。
- RawTableV2 / sidecar 矩阵单元格允许含 `\n`。

### 5.2 规范化：分档展开

新增纯函数模块（建议 `lib/rag/tables/scaleCellTiers.ts`），输入单个「一般规模.建筑面积」类单元格文本，输出：

```ts
type ScaleTierParse =
  | {
      ok: true;
      tiers: Array<{
        bedRangeRaw: string;      // 如 "50-100床"
        buildingAreaRaw: string;  // 如 "2000-4000"
      }>;
    }
  | {
      ok: false;
      reason:
        | "glued_numeric_ranges"
        | "unpaired_lines"
        | "empty"
        | "unsupported_pattern";
    };
```

**匹配规则（首版）**

- 按 `\n` 分行；若无换行但能可靠识别「床位区间 + 面积区间」交替出现，允许同一规则解析。
- 一行像床位档（含 `床` 或仅 `数字-数字` 且量级 < 1000），下一行像建筑面积（`数字-数字` 且量级 ≥ 1000，或带平方米单位）。
- 出现 `床50-1002000-4000` 这类粘连 → `ok: false`，`reason: glued_numeric_ranges`。

**展开策略**

- `ok: true` 且 ≥2 档：将原物理行展开为多条逻辑行，共享设施名/层级/编号等，写入：
  - `规模性指标.一般规模.分档` = 床位档
  - `规模性指标.一般规模.建筑面积(...)` = 对应面积
- `ok: false`：保留原文到字段，但标记 `extractionWarnings` / `lowFidelity`，**不**生成看起来干净的单一数值结论字段。

展开发生在表格对象 → indicator/chunk 之前，避免下游各自猜测。

### 5.3 回答层：配对输出 + 双闸门

1. **分档聚合结论**  
   问「一般规模 / 建筑面积 / 多少平方米」且命中同分档设施多行时：  
   结论格式必须是配对列表，例如：  
   `50-100床：建筑面积2000-4000；100-500床：建筑面积4000-15000；服务规模：每个街道至少1处`。  
   **禁止**合成 `50-500床，2000-15000`。

2. **双闸门**  
   相关依据任一满足 `lowFidelity`、`source_page_required`、或含 `scrambled_numeric_unit`：  
   - 正式【结论】走核原文提示；  
   - **「自动提炼草稿」同步隐藏或同文案降级**，不得继续展示拍扁数值。

3. **依据排序**  
   分档规模题优先配置指标表分档行；配置要求表 / 指标使用说明不得排在其前（沿用并加强既有 structured ranking）。

## 6. 错误处理

| 情况 | 行为 |
|------|------|
| 分档解析成功 | 多逻辑行入库，可确定性作答 |
| 粘连/无法配对 | 低保真标记；拒确定性数值；禁草稿 |
| 单行干净数值（无分档） | 保持现有单行指标行为，不强制展开 |
| 非首版模式（千人指标多行等） | 不展开；不假装已支持 |

## 7. 测试与验收

### 7.1 单元

- 格内保行：含换行的单元格归一化后仍含 `\n`。
- 分档解析：机构养老样例 → 两档配对成功。
- 负例：`床50-1002000-4000` → `ok: false`。
- 回答聚合：禁止拍平；低保真时草稿不可见或同降级。

### 7.2 金标

- 页级：机构养老「一般规模.建筑面积」格抽成两档字段正确。
- 问答：`机构养老设施一般规模是多少` → 两档配对均出现；不出现 `50-500床` 且 `2000-15000` 的拍平表述。
- 负例：脏值样本 → 核原文，无拍扁草稿。

### 7.3 发布验证

对 `北京市居住公共服务设施配置指标京政发〔2025〕25号.pdf` 显式重新解析后，用上述问答手测通过。

## 8. 实现顺序

1. 抽表/归一化保行 + 单测  
2. 分档解析器 + 展开接入对象/chunk 路径 + 单测  
3. 回答分档聚合 + 草稿双闸门 + 单测  
4. 金标与目标文档重解析验收  

## 9. 风险

- 床位/面积量级启发式可能误伤特殊表；用金标约束，失败宁可不展开。  
- 保行后部分旧清洗规则可能失效，需跑既有 table/evidence 相关测试。  
- 仅重解析目标文档后用户侧才看到效果；UI 需提示「需重新解析」。
