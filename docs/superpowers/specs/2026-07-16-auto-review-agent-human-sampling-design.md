# 自动审核 Agent 与人工抽查设计

日期：2026-07-16
状态：已完成交互、架构、风险 Eval、失败处理和验收设计确认

## 1. 决策摘要

本设计继承 `2026-07-15-auditable-review-artifact-pilot-design.md` 的审核副本、来源追溯、
权限隔离和检索主数据只读边界，并在冲突处取代其中的人工全量重点审核、单一审核结果文件和
只能通过重新解析开启新审核的设计。

确定采用以下方案：

- 使用独立混合自动审核 Agent：确定性规则先筛，视觉/语言模型对照原页做独立复核。
- 自动审核只负责发现和排序疑似问题，不阻断文档进入检索。
- 人工主要审核高风险项、重点项和少量低风险稳定抽样。
- 自动审核结论与人工审核结论分别展示、分别计数，不互相覆盖。
- 已提交人工审核轮次永久只读；复审创建独立轮次，不重新解析文档。
- 建立错切风险 Eval，以严重问题召回率为主指标，以误报率为护栏。

## 2. 当前问题与范围边界

### 2.1 截图证据对应的问题

本轮至少要识别以下三类已知异常：

1. 图 1：表格多行、多列和合并单元格内容被揉成乱序文本，标题退化为
   `3.、5、10、15。`，属于阅读顺序异常、单元格粘连和标题失真。
2. 图 2：原表第 15 行的服务规模是 `1000—5000 户`，解析结果却出现
   `20 / 1000—5000 户`，属于跨行字段污染或行边界错误。
3. 图 3：原表中的“指标修改说明”被作为超长 `structured_table_row` 标题和设施名称输出，
   且混入相邻行信息，属于表格层级、字段语义和行归属错误。

### 2.2 本轮目标

- 自动识别上述问题及同类错切状态。
- 给出风险等级、问题类型、简短解释和可核对的来源定位。
- 让人工以抽查为主完成最终确认。
- 让提交后的结果可读、可追溯、不可覆盖，并能独立发起复审。
- 用金标 Eval 证明自动审核的风险排序是否可用。

### 2.3 明确非目标

- 本轮不修改 PDF 表格抽取、行列恢复、合并单元格传播或 Chunk 切分算法。
- 本轮不自动修复解析内容，不重新 embedding，不回写 Chunk 或 RagTable。
- 自动审核发现问题不改变文档的 `indexed` 状态，也不自动下线文档。
- 风险分是抽查优先级，不宣称为真实错误概率。

页面和交付说明必须持续显示以下提醒：

> 本轮只识别切分风险，不修复切分结果；表格仍应按表格结构优化切分。

## 3. 系统边界与数据流

```text
原文件
  → 现有解析、对象化、切片、embedding、RagTable 持久化
  → 文档保持 indexed
  → 从同次处理结果生成不可变审核输入
       ├─ 原页页码与页面图像
       ├─ Block/Table IR
       ├─ KnowledgeObject
       ├─ Chunk / RagTable
       └─ 现有 extractionWarnings / confidence
  → Auto Review Agent
       ├─ 确定性规则检测
       ├─ 原页与解析结果一致性检测
       └─ 语义归属检测
  → auto-review.json
  → 人工抽查轮次 reviews/<reviewId>.json
```

约束：

- 自动审核必须位于索引成功之后，作为独立 sidecar 阶段。
- 自动审核代码不能写 `.data/chunks.json` 或 `.data/ragtables.json`。
- 自动审核失败不能把已经索引成功的文档改成 `failed`。
- Agent 只读取当前审核快照，不读取任何人工审核结果或金标答案。
- 问答 LLM 与自动审核 Provider 分离，不能通过修改问答提示词假装新增审核 Agent。
- `processDocument` 返回同次处理产生的只读快照，审核代码消费该快照，不从落盘 JSON 反向拼装。

## 4. 自动审核 Agent

### 4.1 Provider 边界

新增独立 `AutoReviewProvider`，不复用 `LLMProvider.synthesizeConclusion`。Provider 输入限制为单个
审核项所需的原页、表格上下文、结构化字段和来源元数据；输出必须通过严格 JSON 校验。

运行模式：

- `hybrid`：规则检测与视觉/语言模型均完成。
- `rules_only`：未配置视觉模型时仅运行规则，页面明确标注“自动审核：规则模式”。
- `partial`：部分模型调用失败；失败项不能按“通过”或“低风险”处理。
- `unavailable`：规则和模型都无法形成判断，直接进入人工未审核队列。

配置了模型但调用失败时，不静默降级成完整自动审核。只有 `hybrid` 可以被描述为“独立 Agent
自动审核完成”。

### 4.2 检测信号

确定性信号复用并扩展现有 `classifyEvidenceQuality`：

- 数字、单位和标点阅读顺序异常；
- 表格文本与段落粘连；
- 列数漂移、空表头、异常超长标题；
- 表格行中出现无法在原页目标行定位的值；
- 相邻行值进入当前行；
- 合并单元格层级未传播或传播到错误范围；
- 表头、字段名、对象类型与内容语义不一致；
- 原页页码、表格、行号或来源定位不一致。

模型复核输入包括目标页图像、目标表格上下文、目标行及相邻行、当前结构化字段和确定性信号。
模型不能直接修改规则输出，只能生成独立判断，最终由风险聚合器合并。

### 4.3 单项输出

`auto-review.json` 中每项最小结构为：

```text
auditItemId
status                  # clean | suspected_issue | unavailable
mode                    # hybrid | rules_only | partial | unavailable
riskScore               # 0..100，抽查优先级
riskLevel               # low | medium | high
issueTypes[]
summary
ruleSignals[]
modelAssessment
source
  pageStart
  pageEnd
  tableId
  rowIndex
  blockIds[]
provider
  name
  model
reviewedAt
```

问题类型固定为：

- `reading_order_noise`：阅读顺序或乱码；
- `row_boundary_contamination`：跨行污染；
- `column_misalignment`：错列；
- `merged_cell_scope_error`：合并单元格范围错误；
- `missing_content`：内容缺失；
- `source_mapping_error`：来源定位错误；
- `semantic_assignment_error`：表头、字段、对象类型或内容归属错误；
- `other`：其他可解释问题。

### 4.4 风险聚合

首版采用保守、可解释的最大风险聚合：

```text
riskScore = max(ruleRiskScore, modelRiskScore)
```

规则风险基准：

- 明确的跨行值污染或来源行不存在该值：85；
- 明确的错列或合并单元格范围错误：80；
- 严重阅读顺序、数字单位乱序：70；
- 表头、标题、对象类型和内容语义明显错配：55；
- 仅低置信度且无其他异常：40。

多个规则同时命中不叠加到超过 100；所有输入统一裁剪到 `0..100`。风险等级为：

- 高风险：`70..100`，人工必查并置顶；
- 中风险：`40..69`，纳入重点抽查；
- 低风险：`0..39`，稳定随机抽样。

`partial` 或 `unavailable` 项不能显示为自动通过；它们进入人工“未审核”。模型分数只决定抽查排序，
不能覆盖确定性高风险信号。

## 5. 人工抽查与审核工作台

### 5.1 顶部摘要

顶部固定显示：

- 自动审核主体、模式、模型版本和完成时间；
- 人工审核人、开始时间和提交时间；
- 自动审核范围；
- 重点项完成数；
- 自动疑似问题数；
- 人工确认问题数；
- 自动审核结论；
- 人工审核结论或当前进度。

自动问题数与人工确认问题数不得合并成一个含糊的“问题数”。

### 5.2 默认展示和筛选

- 自动审核存在 `suspected_issue` 时，页面默认打开“问题”筛选。
- 顶部提供“跳到问题”，跳到当前筛选下风险最高且尚未人工确认的项。
- 固定筛选为“问题 / 重点项 / 未审核 / 全部”。
- 问题项按风险分降序，再按页码、表格和行号稳定排序。
- 搜索支持标题、问题类型、页码、表格/行号和人工备注。

### 5.3 单项核对

单项页面并排显示：

- 原页图像和定位信息；
- 当前解析结果；
- 自动审核风险、类型、说明和规则证据；
- 人工结论、问题类型和备注。

界面必须使用“自动审核疑似问题”和“人工审核确认问题”等明确标签，不能只显示“系统已审核”。

### 5.4 人工完成条件

最终提交前必须完成人工确认：

- 所有高风险项；
- 所有重点项；
- 本轮稳定抽中的低风险项；
- 所有自动审核 `partial` 或 `unavailable` 项。

未完成时只能保存草稿。最终人工结论由本轮人工记录汇总：全部通过为 `passed`，存在人工确认问题
为 `issues_found`。

## 6. 只读提交与独立复审

审核产物结构调整为：

```text
artifacts/<docId>/<artifactId>/
├─ manifest.json
├─ review.md
├─ review.html
├─ auto-review.json
└─ reviews/
   ├─ <reviewId>.json
   └─ <nextReviewId>.json
```

每个人工审核轮次包含：

```text
reviewId
artifactId
parentReviewId
reviewerUserId
status                  # pending | draft | passed | issues_found
startedAt
updatedAt
finalizedAt
samplingPlan
items[]
```

约束：

- `finalizedAt` 写入后，该 `reviewId` 永久只读。
- 已提交页面完整显示问题类型、人工备注、自动证据和来源定位。
- “发起复审”创建新的 `reviewId`，并通过 `parentReviewId` 关联上一轮。
- 复审继续引用同一个 `artifactId`，不调用文档解析接口，不重新生成 embedding。
- 旧轮次始终可读；新轮次不能覆盖或删除旧轮次。

## 7. 错切风险 Eval

### 7.1 决策目标

Eval 用于判断自动审核能否安全地排序人工抽查工作，而不是证明切分质量已经修复。主决策是：

- 继续影子试点；
- 调整规则、提示词或阈值；
- 停止使用自动风险排序并回到人工重点审核。

### 7.2 金标集

首版使用约 60 个独立审核项：

- 至少 30 个问题样本；
- 至少 30 个来自相似复杂表格的正确负样本；
- 图 1、图 2、图 3 作为已知问题样本；
- 三张图相邻的正确表格行优先作为难负样本；
- 覆盖阅读顺序、跨行污染、错列、合并单元格范围、缺失、定位和语义归属问题。

金标字段包括真实状态、严重度、问题类型、正确页码/表格/行号和标注说明。按文档及表格分组划分校准集
和盲测集，同一张表的行不能跨集合，避免同表泄漏。此阶段不训练模型，只用校准集调整规则、提示词和
风险阈值，用盲测集报告最终结果。

### 7.3 指标与试点阈值

主指标：

- 严重错切召回率 = 被标为高风险的严重错切 / 全部严重错切，目标 `>= 90%`；
- 严重漏报率 = 未进入高风险的严重错切 / 全部严重错切，目标 `<= 10%`。

驱动指标：

- 来源定位准确率 = 页码、表格和行号均正确的自动问题 / 可定位自动问题，目标 `>= 95%`；
- 问题类型准确率，按多标签逐项计算并输出混淆明细，不使用单一总分掩盖弱类别。

护栏：

- 误报率 = 被报为问题的正确项 / 全部正确项，目标 `<= 15%`；
- 自动审核不可用率 = `partial` 或 `unavailable` 项 / 全部 Eval 项，目标 `<= 5%`。

以上为试点阈值，首次真实运行先记录基线，再判断是否达标；风险分不得展示为统计概率。

### 7.4 运行与报告

新增独立命令 `npm.cmd run eval:auto-review`。报告至少输出：

- 金标集版本、Provider、模型、规则版本和时间；
- 混淆矩阵；
- 主指标、驱动指标和护栏；
- 按问题类型和文档分组的结果；
- 所有漏报、误报和不可用项的来源定位。

没有真实视觉模型配置时，命令只能报告 `rules_only` 基线，不能把结果描述为混合 Agent 验收通过。

## 8. 失败处理

- 审核副本或自动审核整体失败时，处理接口仍返回已经成功的索引结果，并单独返回审核阶段状态。
- 自动审核单项超时、JSON 不合法或来源图像不可用时，该项记录具体原因并标为 `unavailable`。
- 无法完整自动审核时，顶部显示失败项数和原因摘要，不允许显示“自动审核通过”。
- 自动审核文件或静态审核文件哈希不一致时，禁止人工提交并显示完整性错误。
- 当前原文件哈希与 manifest 不一致时，禁止对旧快照提交新结果，但允许读取历史轮次。
- 复审创建失败不能修改已提交轮次。

## 9. 权限与安全

- 复用现有文档管理权限；无管理权限者不能列出、读取、审核或发起复审。
- 原页图像和解析内容只发送给明确配置的自动审核 Provider。
- Provider 请求和错误日志不记录 API Key、完整 base64 图像或整份文档内容。
- 所有模型输出按不可信输入处理：严格 JSON 校验、固定枚举、长度限制和 HTML 转义。
- `docId`、`artifactId`、`reviewId` 均做安全路径校验，禁止路径穿越。

## 10. 测试策略

### 10.1 TDD 单元测试

- 图 1 类样本触发阅读顺序、表格粘连或标题失真信号。
- 图 2 类样本触发跨行污染高风险信号。
- 图 3 类样本触发语义归属或表格层级错误信号。
- 相似但正确的复杂表格不被上述规则误报。
- 风险边界 `39/40/69/70` 映射正确。
- `partial` 和 `unavailable` 不会被汇总为自动通过。
- 模型 JSON 的非法枚举、缺失定位和越界风险分被拒绝。
- 自动/人工摘要分别计数，存在自动问题时默认筛选“问题”。
- 已提交轮次不可覆盖，复审创建新的 `reviewId` 和 `parentReviewId`。

### 10.2 集成验证

- 正常 PDF 处理生成 manifest、审核 HTML、自动审核结果和首个人工轮次。
- 强制自动审核失败后，文档仍为 `indexed`，接口明确返回审核失败状态。
- 无管理权限者访问审核、提交和复审接口均被拒绝。
- 人工最终提交后页面只读且完整显示问题类型、备注和来源定位。
- 发起复审不调用解析接口，不改变 Chunk/RagTable 数量和内容哈希。
- 审核前后 `.data/chunks.json` 与 `.data/ragtables.json` 哈希一致。
- 现有 `npm.cmd test`、类型检查和生产构建继续通过。

### 10.3 真实 Eval

- 使用真实视觉模型运行盲测集并保存报告。
- 检查严重错切召回率、严重漏报率、误报率、定位准确率和不可用率。
- 每次规则、提示词、模型或阈值变化后都必须重跑相同版本盲测集。

## 11. 验收与试点结论

功能验收：

1. 自动审核与人工审核身份、时间、结论和问题数均清晰分离。
2. 自动发现问题时默认展示问题项，“跳到问题”可定位到最高风险未确认项。
3. “问题 / 重点项 / 未审核 / 全部”筛选行为正确。
4. 已提交页面只读并完整展示问题类型、备注和来源定位。
5. 复审创建独立轮次，不重新解析文档。
6. 图 1、图 2、图 3 对应问题均进入自动问题或不可用人工队列，不得被自动标为通过。
7. 审核动作不改变检索主数据。

Eval 结论：

- **继续**：真实混合 Agent 盲测同时达到全部主指标和护栏。
- **调整**：严重召回达标但误报、定位或不可用率未达标；继续影子模式并校准。
- **停止自动排序**：严重错切召回率低于 90%，或存在无法解释的系统性漏报；人工继续按重点项审核。

即使 Eval 达标，表格切分算法仍未修复。后续必须单独立项解决按表格结构切分、合并单元格传播、
跨页续表和行边界恢复问题。
